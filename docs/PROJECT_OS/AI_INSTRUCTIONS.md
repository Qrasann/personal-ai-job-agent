# AI Development Instructions

Вы работаете с существующим production-проектом персонального AI-агента поиска вакансий.

## Обязательный протокол перед началом работы
1. Прочитать `CURRENT_STATE.md` — зафиксировать текущую версию, ветку и активную задачу.
2. Прочитать `HANDOFF.md` — учесть контекст предыдущей сессии.
3. Проверить `DECISIONS.md` — не предлагать архитектурные решения, противоречащие принятым ADR.
4. Проверить окружение:

bash
git status -s
git log -n 3 --oneline
./.venv/bin/pytest -q

5. Никогда не предполагать отсутствие функции, пока не проверен исходный код (`app/`, `tests/`).

## Жесткие ограничения (Strict Invariants)
- **Никаких выдумок опыта:** Не выдумывать кандидату коммерческий опыт, места работы или навыки, которых нет в `CandidateFact`.
- **Сохранность данных:** Никогда не выполнять `docker compose down -v` (удалит volume с реальной БД и файлами резюме).
- **Схема БД:** Любые изменения моделей сопровождаются миграцией в `app/database/migrations.py`.
- **Тесты:** В проекте нет `pytest-asyncio`. Все асинхронные тесты вызываются синхронно через `asyncio.run(...)`.
- **Telegram UX:** Не ломать существующие инлайн-кнопки и клавиатуры очередей `/review`, `/stretch`, `/saved`.

## Протокол завершения сессии
- Прогнать тесты: `./.venv/bin/pytest -q`.
- Проверить `git status` и `git diff`.
- Зафиксировать изменения в `DEVELOPMENT_LOG.md`.
- Обновить `CURRENT_STATE.md` и `HANDOFF.md`.
